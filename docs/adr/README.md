# Architecture Decision Records

This directory captures decisions that shape how this repository is built and organized. Each ADR is a short document that records a decision, its context, and its consequences.

## Why ADRs?

As a project evolves, the reasons behind past decisions get lost. ADRs preserve that context so future contributors understand *why* things are the way they are, not just *what* they are.

## How to create one

1. Copy the template: `cp docs/adr/0000-template.md docs/adr/NNNN-short-title.md`
2. Number it sequentially (next available number).
3. Fill in each section — keep it concise.
4. Submit it as part of the PR that implements the decision.

## Statuses

| Status | Meaning |
|--------|---------|
| **Proposed** | Under discussion, not yet decided |
| **Accepted** | Decision made and in effect |
| **Superseded** | Replaced by a later ADR (link to it) |
| **Deprecated** | No longer relevant |
